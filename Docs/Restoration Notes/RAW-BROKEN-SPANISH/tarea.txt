  4. Plan de port a CMake + gcc/g++ (Arch) + Vulkan

  Este es el trabajo real. LithTech Jupiter es MSVC6/2003 + DirectX 8/9, con mucho windows.h, __asm, __declspec, STL viejo. El port que te propongo:

  Estructura CMake propuesta:
    nolf2_gpl_src/
      CMakeLists.txt (root - options: LITH_VULKAN=ON, LITH_D3D9=OFF)
      cmake/toolchain-arch.cmake
      Engine/
        CMakeLists.txt -> liblithtech (STATIC)
      ClientShell/
      ServerShell/
      Renderer/
        CMakeLists.txt -> renderer_vulkan (cuando LITH_VULKAN=ON)
        d3d/ (legacy, OFF en Linux)
        vulkan/ (nuevo)

  Root CMakeLists.txt mínimo que voy a crear cuando vuelva el sandbox:
    cmake_minimum_required(VERSION 3.27)
    project(LithtechJupiter CXX C)

    set(CMAKE_CXX_STANDARD 17)
    set(CMAKE_CXX_STANDARD_REQUIRED ON)
    set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

    if(NOT CMAKE_BUILD_TYPE)
      set(CMAKE_BUILD_TYPE RelWithDebInfo)
    endif()

    # Arch gcc/g++ - sin flags MSVC
    add_compile_options(-Wall -Wextra -Wno-multichar -Wno-write-strings -fpermissive)
    add_compile_definitions(_LINUX _RETAIL NOMINMAX _HAS_EXCEPTIONS=0)

    find_package(Vulkan REQUIRED)
    find_package(SDL2 REQUIRED) # para windowing/input en Linux (reemplaza Win32)

    option(LITH_VULKAN "Usar renderer Vulkan" ON)

    add_subdirectory(Engine)
    if(LITH_VULKAN)
      add_subdirectory(Renderer/vulkan)
    endif()

  Pasos de compatibilidad gcc/g++:
  1. Reemplazar windows.h -> platform.h shim: DWORD -> uint32_t, HRESULT -> int32_t, MAX_PATH -> 260, __stdcall, __cdecl, __declspec(dllexport) ->
     vacío.
  2. Cambiar stricmp -> strcasecmp, strnicmp, _vsnprintf, direct.h -> unistd.h
  3. Fix for (int i=...) scoping, std::auto_ptr -> std::unique_ptr, falta de std:: en headers viejos.
  4. Ensamblador inline __asm en Math/ y Renderer -> intrínsecos SSE2.

  Renderer Vulkan (nuevo):
  No se puede "agregar soporte Vulkan" con un flag — hay que abstraer. Crearé IRenderer ya existente en Jupiter (d3d_device.cpp, d3d_shell.cpp) y un

  • Usa Vulkan-Hpp + VMA para memoria, SDL2 para VkSurfaceKHR
  • Shaders HLSL *.fx -> glsl -> SPIR-V vía glslangValidator (pipeline en CMake)
  • Validación con VK_LAYER_KHRONOS_validation
